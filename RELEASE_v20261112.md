## Bug
`GET /api/user/export` → `exportAccount()` called `hashEmail(user.email)` unconditionally; `hashEmail` throws `Invalid email` on
null/empty, so any account whose `email_enc` is empty (e.g. a future OAuth sign-up where Facebook withholds the email) got a 500 on a
GDPR feature. Prod impact today: none (all accounts have an email; the CTO verified exports return 200).

## Fix (3 files)
1. `backend/src/lib/accountData.js`
   - `exportAccount()`: hash the email only when there is one; the legacy `OR user_email = $2` clause is added only when a hash exists.
   - `deleteAccount()`: same guard (`norm(email)` empty → no hash), so a whitespace/empty email can never throw mid-deletion.
2. `backend/src/routes/user.js` — `POST /api/user/delete-account`: an account **without** a stored email confirms with the password
   only (it has no address to retype). Accounts with an email still must retype it exactly (unchanged).
3. `frontend/public/account.html` — Delete form: when the account has no email, the "Retype your email" field is hidden and not
   required, so the button enables after the password (before, the browser's `required` check blocked the form).

No database, text or translation changes.

## Tests run (local, real Postgres + Chromium)
- Account with `email_enc = NULL` (+ one result row): profile email `null`; **export → 200** with the result row and `email: null`
  (was 500); delete with wrong password → `DELETE_BAD_PASSWORD`; delete with password only → `ok`, **0 rows left**.
- Account with an email (regression): export 200 incl. results; delete with wrong email → `DELETE_EMAIL_MISMATCH`;
  delete without the email field → `DELETE_EMAIL_MISMATCH` (retype still enforced).
- Browser: no-email account → email field hidden, button disabled until the password is typed, deletion succeeds; no page errors.
- `backend/scripts/smoke.mjs` → **23/23 pass**. `node --check` on both backend files.

## Known limit (for whoever adds OAuth sign-in)
An account with **no email and no password** (pure OAuth) still cannot self-delete: the Account form needs a password and the public
`/delete-my-data` page needs an email. When OAuth sign-in is added, add a re-authentication step (sign in again with the provider)
before deletion. Until then such accounts cannot exist (sign-up always takes an email and a password).
